Task 1 - BFS

Queue is shown from front to back.

Step   Dequeued   Newly enqueued   Queue after
init   -          A                A
1      A          B C              B C
2      B          D E              C D E
3      C          F                D E F
4      D          -                E F
5      E          -                F
6      F          G                G
7      G          -                empty

Visit order: A B C D E F G

1. Marking a node when it enters the queue prevents other nodes from
   adding it again. Its first distance and parent are kept.

2. BFS takes O(V + E) with adjacency lists already in alphabetical order.
   Each node enters the queue once and each edge is checked at most twice
   in an undirected graph. BFS counts edges, so it can choose fewer edges
   with a larger total weight instead of the cheapest path.

Task 2 - DFS

Stack is shown with the top first.

Step   Popped   Action       Pushed in order   Stack after
init   -        push A       A                 A
1      A        visit A      C B               B C
2      B        visit B      E D               D E C
3      D        visit D      -                 E C
4      E        visit E      F                 F C
5      F        visit F      G C               C G C
6      C        visit C      -                 G C
7      G        visit G      -                 C
8      C        skip         -                 empty

Visit order: A B D E F C G
From G: G F C A B D E

1. A node is only marked when it is popped. Before that happens, two
   neighbours can both push it. C is first pushed by A and then by F.
   The older copy of C is skipped at step 8.

2. BFS gives A B C D E F G because its queue takes the oldest entry first.
   DFS gives A B D E F C G because its stack takes the newest entry first.
   DFS follows a branch deeper before returning to the waiting nodes.
   Neighbours are stored alphabetically and pushed in reverse order so
   the alphabetically first neighbour is on top.

Task 3 - Dijkstra

Step   Settled   Updates
init   -         A=0; B=C=D=E=F=INF; all prev values are none
1      A (0)     B=4 via A; C=2 via A
2      C (2)     B=3 via C; D=10 via C; E=12 via C
3      B (3)     D=8 via B
4      D (8)     E=10 via D; F=14 via D
5      E (10)    F=13 via E
6      F (13)    no updates

Node         A      B      C      D      E      F
Final dist   0      3      2      8      10     13
Final prev   none   C      A      B      D      E

1. Relaxation checks whether going through the current node gives a
   cheaper route. B first has cost 4 through A. After C is settled,
   A -> C -> B costs 2 + 1 = 3. Since 3 < 4, B changes to 3 and prev[B]
   becomes C.

2. Dijkstra treats a settled distance as final. A negative edge can later
   give a cheaper route to an already settled node, breaking that rule.
   For example, in a directed graph A -> B=2, A -> C=5, C -> B=-4,
   B would settle at 2 even though A -> C -> B costs 1. In an undirected
   graph a negative edge also allows a negative cycle by going back and
   forth, so a finite cheapest walk may not exist.

   When every weight is 1, total cost equals the number of edges. BFS
   visits nodes in increasing distance like Dijkstra, using a FIFO queue
   instead of searching for the smallest distance.

Running the programs

From the repository folder:
python3 week9/bfs.py
python3 week9/dfs.py
python3 week9/dijkstra.py

output.txt contains the three programs' output in that order.

The queue in bfs.py uses a list and a front index. Enqueue adds to the
back and dequeue advances the front without shifting the other items.
The stack in dfs.py adds and removes at the end of a list. Dijkstra
searches for the unsettled node with the smallest distance each time.
